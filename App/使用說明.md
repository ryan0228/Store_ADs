# Shop Ads 使用說明

## 作業結構

每個商品使用 `yyyyMMdd-NN`，流水號為 `01`～`10`：

```text
20260804-01\
├─ Product_Description.md
├─ Input\
│  ├─ 商品正面.jpg
│  ├─ 商品細節.png
│  └─ 展示動畫.gif
└─ Result\
   ├─ Generated\
   └─ Final\
```

從 `templates\Product_Description.md` 複製唯一的商品說明檔，將全部原始圖片放入 `Input`。不再建立 `01`、`02` 圖片群組，也不再撰寫 `Img_Description.md`。

商品名稱與商品說明必填；商品用途可留白，由 AI 根據名稱、說明與圖片推導中性使用情境。

`廠商文字說明` 是選填欄位。AI 會合併商品描述、廠商文字與圖片中可辨識的文字，去除重複後整理規格、功能、操作與配件。填入中文或日文廠商資料時固定產生最後一張繁體中文摘要圖；沒有廠商文字時，只有資訊量達到 `summary_min_facts` 門檻才產生，資料少時會省略。所有 PNG 右下角會加入「情趣時光」品牌圖。單影格 GIF 視為靜態圖片；多影格 GIF 各自原樣輸出，不加入品牌圖。

## AI 設定

1. 複製 `config.local.example.toml` 為 `config.local.toml`。
2. 只在 `config.local.toml` 填入 OpenAI 或 Google API key。
3. 在 `config.toml` 的 `[ai]` 選擇 `provider` 並設定該供應商支援的 `model`。

`summary_min_facts` 預設為 `3`：沒有廠商文字時，圖片文字與描述檔去重後至少有三項具體資訊，才會產生最後摘要頁。數字調高會減少摘要頁，調低則更容易產生。

`config.local.toml` 已被 Git 忽略，不得改名後提交、放入 ZIP 或傳給其他人。程式不會將 API key 寫入 Log、Manifest 或 EXE。

## 日常流程

1. 雙擊 `NewJob.cmd`；程式以今天日期自動建立下一個 `yyyyMMdd-NN`，並開啟描述檔與 Input。
2. 填寫 `Product_Description.md`，將所有來源圖片放入 `Input`。
3. 雙擊 `ValidateLatest.cmd` 檢查最新商品作業。
4. 雙擊 `AnalyzeLatest.cmd`；靜態圖會先縮小並移除 metadata，每個動畫 GIF 只擷取首、中、末代表影格供 AI 排序，不上傳完整 GIF。
   程式會先略過內容完全相同的重複圖片（所有支援格式皆適用），保留自然排序最前的一份；Input 原檔不會被刪除，略過原因會顯示在 Log 與預覽中。
5. 開啟作業目錄的 `Work\preview.html`，確認圖片分組、順序、文案、圖片文字擷取內容與最後摘要頁；尺寸、材質、功能及配件必須能在描述檔或圖片中找到依據。
6. 雙擊 `GenerateLatest.cmd`，依 `Work\ai-plan.json` 產生 `Result\Generated`。
7. 目視確認後將成品複製到 `Result\Final`。
8. 雙擊 `PackageLatest.cmd` 建立跨電腦 ZIP。

`NewJob.cmd` 會從 `01`～`10` 找出第一個未使用編號，且不會覆蓋既有作業。指定日期或只建立不開啟視窗可使用：

```powershell
ShopAds.exe new-job --date 2026-08-04 --no-open
```

AI 只規劃使用者提供的原圖與產生繁體中文文案，不生成、重畫、換背景或修改商品。動畫 GIF 只依計畫重新命名並原樣複製。

## 開發命令

```powershell
python -m shopads validate D:\CASE\Shop_ADs\20260804-01
python -m shopads analyze D:\CASE\Shop_ADs\20260804-01
python -m shopads generate D:\CASE\Shop_ADs\20260804-01
```

重新測試並建立 `ShopAds.exe`：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
```
